## Hermes 主機接線

### 1. 準備執行環境

- [ ] checkout 已包含 Hermes outbox 功能的專案版本。
- [ ] `node --version`、`python --version`、`hermes --version` 均可執行。
- [ ] 專案依賴已安裝，`server/.env` 在 Hermes 主機可用。
- [ ] Supabase service-role／secret 只留在 `server/.env`，不得貼進 Cron prompt、聊天或 log。
- [ ] 記下 Hermes 主機的專案絕對路徑，供 `--workdir` 與 `MEDIA_PLATFORM_PROJECT_ROOT` 使用。

### 2. 安裝 pre-check gate

macOS／Linux：

```bash
mkdir -p ~/.hermes/scripts
cp scripts/hermes/media-inbox-gate.py ~/.hermes/scripts/media-inbox-gate.py
export MEDIA_PLATFORM_PROJECT_ROOT="/absolute/path/to/media_platform_notion_antigravity"
python ~/.hermes/scripts/media-inbox-gate.py
```

Windows PowerShell（只有 Hermes 確實運行在另一台 Windows 時才使用）：

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.hermes\scripts"
Copy-Item scripts\hermes\media-inbox-gate.py "$env:USERPROFILE\.hermes\scripts\media-inbox-gate.py"
setx MEDIA_PLATFORM_PROJECT_ROOT "D:\absolute\path\to\media_platform_notion_antigravity"
python "$env:USERPROFILE\.hermes\scripts\media-inbox-gate.py"
```

驗收：最後一行只能是合法 JSON；沒有待處理資料時為
`{"wakeAgent":false}`，有資料時為 `wakeAgent=true` 並帶 bounded outbox IDs。

### 3. 建立帶通知的 Hermes Cron

- [ ] 先用 `hermes cron create --help` 核對該主機版本的參數。
- [ ] 設定明確 `--workdir`、`--script media-inbox-gate.py` 與通知目標。
- [ ] 通知優先指定實際已連線的頻道；沒有確認頻道時不得宣稱錯誤會送達。
- [ ] Prompt 必須限制：每次只處理最舊一筆、不得使用 `--execute-poc`、不得發布、不得安裝套件、不得修改專案。

參考命令：

```bash
hermes cron create "every 30m" \
  "Read at most 10 pending items. Process only the oldest item with node scripts/agent-sdk/analyze-item.js and agent identity hermes:cron:media-inbox. Never use --execute-poc. Never publish, install packages, or modify a project. Report proposals and failures; respond [SILENT] only when no item exists." \
  --script media-inbox-gate.py \
  --workdir "/absolute/path/to/media_platform_notion_antigravity" \
  --deliver all \
  --name "Media inbox review"
```

## 跨電腦 E2E 驗收

### 5. Happy path

- [ ] 從正式入口丟入一篇新的測試文章到 `/api/process`。
- [ ] API 回傳 `postId` 與 `outboxEventId`。
- [ ] `collection_posts.title` 保存新文章標題。
- [ ] Outbox 初始為 `pending`，沒有殘留錯誤或鎖。
- [ ] Hermes 只 claim 一次；完成後 lease 清除。
- [ ] `collect` scope 變成 `sent`，不產生行動路由。
- [ ] `research`／`poc_proposal` 只保存 proposal，保持等待人工決定。
- [ ] Hermes 結果送到指定通知頻道，不能只存在本機 output。

### 6. Failure drill

- [ ] 只使用 disposable 測試來源或測試環境，不破壞正式收藏。
- [ ] 人為製造一次可控制的分析錯誤。
- [ ] CLI 非零結束。
- [ ] Outbox 成為 `failed`，`last_error` 包含 stage、agent、timestamp、type、message。
- [ ] Hermes 通知頻道收到失敗訊息。
- [ ] 人工決定 retry／close 前不做無限自動重試。

### 7. 人工核准邊界

- [ ] `collect`：只收藏，流程結束。
- [ ] `research`：只提出研究方向，不自動查網路。
- [ ] `poc_proposal`：只提出 POC；實際執行必須經 POC Workbench 的 `EXECUTE_POC` 確認。
- [ ] 原作者貼文不得自動改寫。
- [ ] 不自動建立 `agent_jobs`，不啟用常駐 Outbox Dispatcher。
