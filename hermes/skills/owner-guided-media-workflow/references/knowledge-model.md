# Knowledge model

| Object | Purpose | Boundary |
| --- | --- | --- |
| Source | Original post, article, image, video or prompt and its provenance | A source claim is not an established fact |
| Collection | Browsing and retrieval folder | Filing does not mean understanding or endorsement |
| Topic | A long-running research question and evolving understanding | Independent of repositories and Projects |
| Project | A concrete outcome, constraints, decisions and verification | Includes software, investment research, content initiatives and business experiments |
| Knowledge note | Reusable understanding with evidence and conditions | May exist conceptually before a Topic; use only supported persistence |
| Output | Article, prompt, image, video or implementation artifact | Optional reuse; never a prerequisite to knowledge completion |

These are relationships, not nested folders or mandatory form fields. Sources may support multiple Topics and Projects. Respect actual schema cardinalities (including existing primary/related Topic limits); propose a migration rather than silently exceeding them.

Keep four epistemic states distinct: raw source statements; AI extraction/inference; Owner's provisional understanding; evidence-backed verification results. These are semantic labels, not instructions to invent database enum values.

For a knowledge note retain: statement, applicability, source revision/locator references, Owner decision and conditions, unresolved questions, counterevidence, revision history. AI proposals remain labelled. Topic synthesis links reusable knowledge and preserves uncertainty; it does not copy full posts. A Project records goal, current obstacle, decision rationale, next experiment and observed outcome when supported.

Collection recommendations may be automatic. Accepted filing uses the audited server path and current Owner-approved taxonomy. Never silently create categories, Topics or Projects. Suggest readable names; Owner acceptance can approve an agent-proposed name. Make the complete current choice list accessible within the same review, with search/pagination when supported.

Do not duplicate a source to place it in several Topics. Rejected and deferred ideas remain traceable but never become accepted knowledge. Correct prior understanding by a new revision with rationale, retaining the prior decision.
