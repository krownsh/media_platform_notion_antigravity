# Project application and optional outputs

## Project decisions

Include software and non-software goals. Turn a useful knowledge link into a candidate decision or experiment only when it helps a concrete goal. Record expected benefit, assumptions, effort, evidence to collect and stopping condition. Let the Owner choose investment and priority; avoid converting every interesting idea into a new task.

Distinguish proposing, authorizing execution, executing and verifying. A successful test supports only its observed conditions. Feed adopt/defer/reject outcomes back to knowledge and preserve failures as evidence.

Perform task-relevant read-only research within the existing request and access scope; do not demand separate approval for each public page. Installation, paid execution, credentials, repository changes, publication, restarts and deployment require applicable authorization for the action and target. Honor authorization already given; collection, Topic acceptance or Project linking alone does not supply it.

Before an authorized POC, define isolation, evidence, stop conditions and recovery. Never silently modify a production project. For deployment identify revision, worktree impact, migrations, backup/readback, restart scope and smoke verification.

## Content creation branch

Use when requested or within an explicitly configured output policy. Knowledge synthesis remains primary. Do not automatically turn all high-priority sources into publishable drafts.

Allow single-source creation now and later multi-source enrichment; never wait for unknown future sources. Source selection signals creative potential, not permission to invent the Owner's opinions or publish.

Support long-form rewriting, social text/cards, reusable prompts/workflows, image concepts, video concepts/scripts and business hypotheses as relevant. Distinguish artifacts (article/prompt/video) from goals (side income/profit). Do not force every source into every format.

Preserve source provenance, original versus generated prompts and untested versus tested workflows. Ask for audience, format or stance only when missing information changes the result materially. Mark AI-added positions as proposals. Drafting, rendering and publishing are separate states; publication needs authorization. Creative completion does not automatically accept underlying knowledge or overwrite Topic understanding.
